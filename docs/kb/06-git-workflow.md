# 06 · Git 与 Cursor 工作流

## 混合策略（已采用）

| 层 | 作用 | 形式 | 是否进远程 |
|----|------|------|------------|
| 业务守则 | 模块组成 + 跨模块影响 | 仓内 `asin-lens-sop.mdc` + 业务 `asin-lens-*.mdc` | ✅ 须上传 |
| 业务知识库 | 契约 / 采集 / 报告 / 前端产品 / 基建 | `docs/kb/00`–`05`、`vendor` | ✅ 须上传 |
| 对话卫生 | 省上下文、准备上新、push 话术 | 本机 `~/.cursor/rules/asin-lens-chat-hygiene.mdc` | ❌ 不上传 |
| 洁癖 skill | 收尾流程 | 本机 `~/.cursor/skills/neat-freak/` | ❌ 不上传 |

## 上传分流（业务 vs 对话）

| 类型 | 含义 | push |
|------|------|------|
| **组成部分** | 各模块源码、用户可见前端、支撑其运转的 API/schema | ✅ |
| **组成部分之间的影响规则** | 契约、双报告边界、Sif 能力边界、业务 kb、业务 Cursor rules、changelog | ✅ |
| **对话卫生** | 帮 AI 理解对话、省上下文、交接模板、入库话术 | ❌ 仅本机 |

## 针对性开发节奏

1. 从业务模块树或 `docs/kb/INDEX.md` 选模块  
2. `git checkout -b mod/<模块>`  
3. 新对话声明 `mod/<名>`；对话交接见本机「准备上新」规则  
4. 计划 →「确认执行」→ 改代码  
5. 业务改动：本地 commit；你说 **push** 则上传（含对应 kb/契约/changelog）  
6. 对话卫生改动：只写本机 rules/skills，不必进仓  
7. 你说 **洁癖**：对齐业务文档与代码；业务侧可随后 push；不上传对话卫生  

## 禁止

- 未确认改 Schema/跨模块契约  
- 把对话卫生规则误 push 进远程冒充业务契约  
- 业务契约 / vendor 边界只留在本机导致技能无法运转  
- 擅自 force push；客户 UI 挂开发模块树
