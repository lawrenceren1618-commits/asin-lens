# 06 · Git 与 Cursor 工作流

## 混合策略（已采用）

| 层 | 作用 | 形式 |
|----|------|------|
| 全局守则 | 行为约束，每次对话自动带上 | `.cursor/rules/asin-lens-sop.mdc`（含洁癖底线） |
| 模块知识库 | 业务细节，按需阅读 | `docs/kb/*.md` |
| Vendor schema | 外部 MCP 能力边界 | `docs/vendor/**` |
| 文件规则 | 打开相关代码时提醒读 kb | `asin-lens-*.mdc` globs |
| 模块树 | 不忘文件名与区块名 | **全局规则**置顶表（非客户 UI）；详表 `INDEX.md` |
| 洁癖收尾 | 文档/规则与代码对齐 | 个人 skill `neat-freak`（说「洁癖」） |

## 本地入库 vs 远程上传

| 类型 | 本地 commit | push 远程 |
|------|-------------|-----------|
| 影响前端使用效果（UI/静态资源/改变页面结果的 API） | ✅ | ✅（你说 push） |
| 规则 / kb / AGENTS / 洁癖 / 纯文档 | ✅ | ❌ 默认不传（Cursor 读本机即可） |

例外：你明确说「全量 push / 文档也推远程」时才上传文档类。

## 针对性开发节奏

1. 从全局规则置顶「模块树」或 `docs/kb/INDEX.md` 选模块  
2. `git checkout -b mod/<模块>`  
3. 新对话粘贴开聊模板（见 INDEX）；模块树已由 alwaysApply 规则自动带上  
4. Agent 出计划 → 你「确认执行」→ 再改代码  
5. **本地入库**：规则/kb/洁癖类改完就 commit；不自动 push  
6. **你说 `push`**：仅当有「影响前端使用效果」的提交时才 `git push`；纯文档则只本地入库并说明  
7. **你说 `准备上新`**：估上下文；约 ≥70% 则建议换对话 → 拆模块并生成开聊模板  
8. **你说 `洁癖`**：neat-freak 收尾（对齐 kb/规则；删除须再确认；结果默认只本地入库）  
9. 发版另需你确认版本名；发版对象应是前端效果相关提交  

## 禁止

- 未确认改 Schema/跨模块契约  
- **把纯规则/kb 误当成必须 push**  
- 擅自 force push  
- 在一个对话里无边界地改所有模块  
- 把开发用模块树挂到客户可见前端
